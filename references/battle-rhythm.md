# Battle rhythm — how to run recurring things so they actually stick

*No volatile figures in this file. It explains a cadence method.*

A **battle rhythm** is the military's word for the recurring cycle of events that keeps an
operation synced — the standups, the syncs, the reviews that happen on a known schedule so nobody
has to re-decide them. You already lived inside one. Out here (or before you're in), nobody sets
it for you. So you set it — and it does the work that motivation can't.

## Why rhythm beats motivation

Motivation is weather; rhythm is climate. When the next action is *already decided* — "Monday
morning I run `/next-move`," "Sunday night I run `/aar`" — you don't spend willpower deciding
whether to do it. You just run the rhythm. On the hard days, that structure is the thing that
carries you, exactly like a duty schedule did.

## How to set one that holds

1. **Start smaller than feels right.** One daily thing, one weekly thing. A rhythm you keep beats
   an ambitious one you abandon in a week.
2. **Anchor it to something that already happens.** Right after morning coffee. Sunday before the
   week starts. Attach the new habit to an existing one.
3. **Make each item produce something.** "Think about the job search" is not a rhythm item. "Run
   `/next-move` and do the one thing it names" is.
4. **Review the rhythm itself.** In your weekly `/aar`, ask whether the rhythm is right — kill
   what you never do, keep what moves the mission.

## A starter rhythm

- **Daily:** `/next-move` → do the one action it names.
- **Weekly:** `/aar` → what moved, what didn't, what changes. Then `/level-up` → one thing to
  make easier next week.
- **At every milestone or stage change:** re-run `/onboard` so the whole system re-points.

Your real rhythm lives in `comms/battle-rhythm.md`. Edit it until it fits your actual week — then
keep it.
